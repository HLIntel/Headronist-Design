# Composition-First Design

*Design foundations · Tags: composition, hierarchy, typography, layout · [Documentation index](README.md)*

Choose the information hierarchy before styling. Use editorial, product, documentation, data, or campaign composition based on the content. Avoid repetitive card grids, badge-heavy sections, generic gradient blobs, decorative emojis, excessive empty space, and unnecessary animation.

Prefer readable prose, intentional asymmetry, genuine screenshots, simple separators, and one strong visual focal point. Use cards only for genuine grouping or interaction. Typography and section rhythm should carry hierarchy.

Run `python -m headronist.composition path/to/page.html` for cheap structural warnings. Counts are advisory, not universal limits. This check does not verify browser rendering, whitespace, visual quality, accessibility, or overlap. Inspect actual screenshots across viewport widths and zoom levels.

Further reading: Nielsen Norman Group visual hierarchy principles; IBM Design Language layout guidance; web.dev layout stability guidance.
